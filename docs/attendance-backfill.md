# 补卡功能首版产品方案

## 一、背景与目标
- 现有产品有每日工作记录入口，适合顺手标记漏打卡
- 目标是让用户低成本记录漏打卡，并在指定日期邮件提醒，辅助用户在自己的审批系统完成补卡

## 二、范围与非目标
### 范围
- 手动记录漏打卡日期与类型（上班、下班）
- 当月补录与次数统计
- 按配置日期与时间发送月度汇总邮件
- 个人配置：补卡次数上限、推送日期、推送时间、汇总范围、收件邮箱

### 非目标
- 不接入打卡系统数据
- 不提供审批系统代提交流程
- 不提供自定义邮件模板
- 不提供导出清单

## 三、核心规则
- 次数口径：每条记录计 1 次，上下班分开计数
- 次数上限：达到上限后禁止新增
- 日期范围：仅允许当月记录与补录，不允许跨月
- 推送策略：当月无记录不发送
- 锁定规则：当月邮件推送后，该月记录不可修改

## 四、方案对比与选择
### 方案对比 1：列表视图与日历视图
- 列表视图：新增、补录、删除操作效率高，适合快速管理
- 日历视图：日期分布直观，但编辑成本高
- 选择：列表视图为主，月度分布可作为后续增强

### 方案对比 2：整月锁定与批次锁定
- 整月锁定：规则清晰，用户易理解，实现简单
- 批次锁定：更灵活，但规则复杂、理解成本高
- 选择：整月锁定

### 方案对比 3：平台统一发信与用户邮箱授权
- 平台统一发信：配置简单，上手成本低
- 用户邮箱授权：可控性高，但配置复杂
- 选择：平台统一发信

## 五、用户流程
1. 用户在每日工作记录中标记漏打卡（上班或下班）
2. 支持补录当月历史日期
3. 系统展示当月补卡次数已用与上限
4. 到达推送日期与时间，系统发送当月补卡清单邮件
5. 推送后锁定当月记录，禁止修改

## 六、功能清单
- 记录管理：新增、补录、删除漏打卡
- 次数统计：当月已用次数与上限展示
- 推送配置：推送日期与时间、收件邮箱、当月汇总
- 邮件推送：固定模板生成与发送

## 七、页面结构（首版建议）
- 顶部：当月补卡次数用量条（已用/上限）
- 主区：漏打卡列表（日期、类型、备注、状态）
- 操作区：新增与补录入口
- 侧区：推送配置（日期、时间、收件邮箱）

## 八、邮件模板（固定）
- 标题：本月补卡清单提醒
- 正文结构：
  - 本月补卡次数：已用/上限
  - 日期表格：日期 + 类型（上班/下班）
  - 提示文案：请在审批系统提交补卡申请

## 九、异常与边界
- 推送日期超过当月天数：自动调整为当月最后一天
- 当月无记录：不发送邮件
- 达到上限：禁止新增并提示
- 推送后修改：禁止并提示

## 十、首版不做项
- 邮件失败重试与送达保障
- 邮箱验证流程
- 预提醒或多次提醒
- 批量导出与自定义模板
